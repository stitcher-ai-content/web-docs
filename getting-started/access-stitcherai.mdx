StitcherAI has two surfaces: the **web app**, where you manage connections, runs, and schedules, and the **authoring environment**, where you build the cost model itself. Each has its own one-time setup, covered below.

## Prerequisites

- Access to the relevant [environment](/security/access-and-administration) — provisioned by StitcherAI and based on your organization's identity provider
- GitHub access to your pipeline configuration repo — see [Access & administration](/security/access-and-administration)

## The web app

The web app at **[app.stitcher.ai](https://app.stitcher.ai)** is where you operate StitcherAI day to day. From it, you can:

- Manage **environments** and switch between the ones you have access to
- Configure **data connections** — sources and destinations
- Invoke and monitor a pipeline **run** — standard, scheduled, and debug
- Manage **schedules**

<Steps>
  <Step title="Sign in">
    StitcherAI provisions your account — your email and password. Organizations can optionally connect their own identity provider via SAML for single sign-on with a corporate identity.

    <Frame caption="Signing in to the web app with a work email.">
      <img src="/images/quickstart-webapp-login.png" alt="Signing in to the web app with a work email" />
    </Frame>
  </Step>
  <Step title="Confirm your environment">
    Once signed in, you land in the [environment](/security/access-and-administration) your role grants you access to. If you work across more than one environment, you can switch between the ones you have access to from within the app.
  </Step>
</Steps>

## The authoring environment

The authoring environment is where you build the cost model, in a VS Code editor. From it, you can:

- Build the model through **visual forms** with per-stage validation and field help, or work with the underlying configuration directly
- Use the **AI chat side-by-side** to make multi-stage edits, reviewing its plan as an inline checklist before it applies changes

<Note>
  AI chat, the schema browser, and autocomplete are available only once you're logged in to the StitcherAI extension with your StitcherAI account — logging in is what turns the editor from a text view into the full authoring environment.
</Note>

### The easiest way — edit a pipeline from the web app

From the web app, open **Pipelines**, find your pipeline, and click the **GitHub icon** in the Actions column. From the menu that opens, choose **Edit pipeline configuration** (the same menu also offers **Visit repository**, for browsing the repo on GitHub directly). This opens a new browser tab running VS Code for the Web, already pointed at your pipeline configuration repo — no local install required.

<Frame caption="The Pipelines list in the web app: opening a pipeline's Actions-column GitHub-icon menu, with Visit repository and Edit pipeline configuration.">
  <img src="/images/quickstart-edit-pipeline-button.png" alt="Opening a pipeline's Actions-column GitHub-icon menu, with Visit repository and Edit pipeline configuration" />
</Frame>

<Steps>
  <Step title="Sign in with your GitHub account">
    GitHub hosts your pipeline configuration repo, so this is what grants access to it. This is a **separate identity** from your StitcherAI account.
  </Step>
  <Step title="Install the StitcherAI extension">
    Click the **Extensions** icon in the Activity Bar, search for **StitcherAI**, and click **Install**.

    Turn on **Auto Update** for the extension so you always stay on the latest version.

    <Frame caption="Searching for and installing the StitcherAI extension from the Extensions view.">
      <img src="/images/quickstart-stitcherai-extension-install.png" alt="Searching for and installing the StitcherAI extension" />
    </Frame>

    The first time, VS Code asks you to **trust the extension's publisher** and to **trust the workspace** — confirm both. These are one-time prompts per browser.
  </Step>
  <Step title="Log in to the StitcherAI extension">
    Click **log in**; a browser tab opens to sign in with the same identity you use for the web app. You're also asked to **trust the domain** — confirm it (another one-time prompt). Confirming completes the login and hands control back to VS Code.

    <Frame caption="Logging in to the StitcherAI extension from the start page.">
      <img src="/images/quickstart-extension-login.png" alt="Logging in to the StitcherAI extension from the start page" />
    </Frame>
  </Step>
</Steps>

## Setting up locally (alternative)

If you'd rather work in a local, desktop copy of VS Code, you can set it up by hand instead. This is not the usual path — most people use the browser flow above.

<Steps>
  <Step title="Install VS Code">
    Download and install [VS Code](https://code.visualstudio.com) for your operating system, then open it.

    <Frame caption="The Extensions icon in VS Code's Activity Bar.">
      <img src="/images/quickstart-vscode-extensions-icon.png" alt="The Extensions icon in VS Code's Activity Bar" />
    </Frame>
  </Step>
  <Step title="Install the StitcherAI extension">
    Open the **Extensions** view — click the Extensions icon in the Activity Bar on the left (or press **Ctrl+Shift+X** on Windows/Linux, **Cmd+Shift+X** on Mac). Search for **StitcherAI** and click **Install** on the [StitcherAI extension](https://marketplace.visualstudio.com/items?itemName=StitcherAIInc.stitcherai-editor).

    Turn on **Auto Update** for the extension so you always stay on the latest version — the same Extensions view as above.
  </Step>
  <Step title="Clone your pipeline configuration repo">
    Find the repository URL in the web app: **Pipelines → your pipeline → Visit repository**.

    <Frame caption="Finding a pipeline's repository URL in the web app: Pipelines → your pipeline → Visit repository.">
      <img src="/images/quickstart-visit-repository.png" alt="Finding a pipeline's repository URL in the web app" />
    </Frame>

    Then use VS Code's built-in Git support: open the Command Palette (**Ctrl+Shift+P** on Windows/Linux, **Cmd+Shift+P** on Mac), run **Git: Clone**, paste the repo URL when prompted, then choose a folder on your machine to clone it into.

    If you're comfortable with the command line, this does the same thing:

    ```bash
    git clone <your-pipeline-repo-url>
    ```
  </Step>
  <Step title="Open that repo in VS Code">
    If you used **Git: Clone** above, VS Code offers to open the cloned folder right away — accept that. Otherwise, use **File → Open Folder...** (Windows/Linux) or **File → Open...** (Mac) and select the folder you cloned.
  </Step>
  <Step title="Log into the StitcherAI extension">
    With the repo open, click **log in** in the StitcherAI extension. A new browser tab opens — sign in with the same identity you use for the web app. You're also asked to **trust the domain** — confirm it (another one-time prompt). Confirming completes the login and hands control back to VS Code.
  </Step>
</Steps>

<Note>
  Log in only **after** opening your pipeline configuration repo. The extension needs that project context to complete the login loop — logging in first, or with the wrong folder open, means the browser confirmation won't connect back to VS Code.
</Note>

## Verify it worked

Once logged in, the **Welcome to StitcherAI** start page appears, with **Start a Chat**, **Quick Start Guide**, and **Manage Pipeline** actions, and the four stages — Connect, Model, Build, Engage — laid out below.

Open the **Schema Browser** (the icon in the top bar, next to the AI chat icon) to confirm your data is connected. Right after logging in it shows a spinning icon while metadata is retrieved:

<Frame caption="The Schema Browser icon while metadata is being retrieved, right after logging in.">
  <img src="/images/quickstart-schema-browser-updating.png" alt="The Schema Browser icon while metadata is being retrieved" />
</Frame>

Once that finishes, it shows **Metadata refreshed at [time]**. From there you can browse by stage, by data source, or by column.

<Frame caption="The Schema Browser once metadata has refreshed, with browse-by-stage, -data-source, and -column options.">
  <img src="/images/quickstart-schema-browser.png" alt="The Schema Browser once metadata has refreshed" />
</Frame>

If you don't see these, confirm your pipeline configuration repo is still the open folder, then log out and back in.
