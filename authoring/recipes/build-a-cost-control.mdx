## What this does, and why

[Govern](/pipeline/build/govern) evaluates a generated artifact and turns a policy breach into a routed alert. This guide walks through building one **control group** — the unit you name, point at an artifact, and attach one or more controls to.

<Note>
  This assumes a generated artifact already exists to govern (see [How to: Generate an artifact](/authoring/recipes/generate-an-artifact)). This guide governs the `effective_cost_by_team` indicator built there, continuing straight from it.
</Note>

## Add a control group — general configuration

<Steps>
  <Step title="Control group name">
    A label for change management, auditing, and downstream reporting — it doesn't appear in the output dataset itself.
  </Step>
  <Step title="Artifact group (optional)">
    Group this control evaluation with others; the name is used for routing during Engage if the destination is an object store. Limited to alphanumeric characters, underscores, dashes, and spaces. Left blank, the evaluation is assigned to a `default` group.
  </Step>
</Steps>

## Select the source artifact

<Steps>
  <Step title="Source artifact type">
    Choose the kind of artifact this control group evaluates — **Primary dataset** (the normalized cost dataset produced by Model), a **Time series indicator**, or a **Derived dataset** — then pick the specific artifact.
  </Step>
  <Step title="Enable scope (optional)">
    Limit the evaluation to a subset of the source artifact.
  </Step>
  <Step title="Filters (optional)">
    Ring-fence which rows this control group evaluates — a **simple condition** (column, operator, value) or a **SQL condition**.
  </Step>
  <Step title="Columns to override (optional)">
    Add or override a column on the cost dataset with a constant value or an expression, each with a name and a value. For anything needing conditional logic, do that upstream in Model (Prepare or Enrich) with Lookup, Mapping, or Unpack instead.
  </Step>
</Steps>

<Tip>
  A simple condition supports the operators `=`, `!=`, `>`, `>=`, `<`, `<=`, `is null`, `is not null`, `in`, `not in`, `like`, and `not like` — for example `Provider = 'AWS'` or `x_ApplicationId >= 123`.
</Tip>

## Add controls

Add one or more controls to the group. For each:

<Steps>
  <Step title="Control type">
    **Row-level control** evaluates each row independently and records a pass/fail per row, so you can identify exactly which rows are non-compliant. **Aggregate-level control** evaluates the dataset as a whole, producing a single pass/fail per condition.
  </Step>
  <Step title="Name">
    The control's name.
  </Step>
  <Step title="Failure handling">
    **Evaluate until first failed condition** stops early, when one failure is enough to act on. **Evaluate all conditions** shows the complete picture of every breach in one pass.
  </Step>
  <Step title="Evaluation conditions">
    One or more conditions — the same simple-condition / SQL-condition choice used for filters, now expressing the policy test itself (for example, a column compared against a threshold).
  </Step>
</Steps>

<Note>
  A failed control raises an alert, routed by the condition's tags to the owning team, a channel, or an email group. See [Govern](/pipeline/build/govern) for the full alert-routing concept.
</Note>

## Worked example — govern the effective-cost-by-team indicator

<Steps>
  <Step title="General configuration">
    Control group name `effective_cost_by_team_threshold`. No artifact group needed for a first pass.
  </Step>
  <Step title="Select the source artifact">
    Source artifact type: **Time series indicator**. Artifact: `effective_cost_by_team` (built in [How to: Generate an artifact](/authoring/recipes/generate-an-artifact)). No filters or column overrides needed.
  </Step>
  <Step title="Add a control">
    Control type **Row-level control** — one pass/fail per team, per month. Name `team_cost_threshold`. Failure handling **Evaluate all conditions**, so every team that breaches shows up, not just the first. One evaluation condition: a simple condition on the indicator's aggregated cost column, operator `>`, value the monthly threshold.
  </Step>
</Steps>

Every team-month row that exceeds the threshold fails the control and raises an alert — closing the loop from [Generate an artifact](/authoring/recipes/generate-an-artifact) straight through to governance.
