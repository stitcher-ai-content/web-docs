The cost model is versioned in Git, but you work with it visually. Branching, check-in, and pull requests happen in **VS Code's source-control panel** inside the StitcherAI Editor; **tags** — which pin a configuration version to the cost periods it applies to — are managed in the **web app**.

<Note>
**No command line required.** Everything on this page happens in VS Code's source-control panel or the web app.
</Note>

## Branch, change, and review — in VS Code

<Steps>
  <Step title="Create a branch">
    In the source-control panel, create a branch so your change is isolated from what's running.
  </Step>
  <Step title="Make the change">
    Use [forms](/authoring/forms-and-autocomplete), the configuration text, or [AI chat](/authoring/ai-chat). The assistant sees your **uncommitted edits**, so you can iterate before checking anything in.
  </Step>
  <Step title="Check changes in">
    Stage and commit ("check in") your edits with a message. Push when you're ready — **unpushed branches are fine**: chat and validation work on them too.
  </Step>
  <Step title="Validate the branch">
    Run **Validate Configuration** for a rules check without a run, then a scoped [debug run](/operating/running-and-monitoring) against the branch to see it execute on real data.
  </Step>
  <Step title="Open a pull request">
    Open a pull request for peer review. Your repository's review and branch-protection rules apply — see [Access & administration](/security/access-and-administration).
  </Step>
</Steps>

<Info>
Opening the pull request from **inside the StitcherAI Editor** is coming soon. Until then, open it from the source-control panel's GitHub view or on GitHub.
</Info>

## Tags — in the web app

A **tag** assigns a configuration version to the **cost period(s) it applies to**, so a historical run reproduces exactly. You manage tags in the web app, not in Git tooling.

<Frame caption="Managing tags in the web app: assigning a configuration version to the cost periods it applies to">
  ![Managing tags in the web app: assigning a configuration version to the cost periods it applies to](/images/fig-19-web-app-tags.png)
</Frame>

<Tip>
Branching and review give the model software-grade change control; tags make past runs replayable. A [standard run](/operating/running-and-monitoring) uses the tag to pick the right configuration for the period it processes.
</Tip>

## Who does what

| Concern | Where |
|---|---|
| Branch · check in (commit) · pull request | VS Code source-control panel, in the editor |
| Tag a configuration version to cost periods | Web app |
| Review rules and branch protection | Your GitHub repository — see [Access & administration](/security/access-and-administration) |
