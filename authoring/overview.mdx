The cost model is a set of configurations — one per stage, **Connect · Model · Build · Engage** — kept in a Git repository your organization owns. The **StitcherAI Editor**, a VS Code extension, turns that repository into a guided authoring environment: each stage renders as a form, each configuration is checked against the rules of its stage, and once you sign in you get a browser of your available data, schema-aware autocomplete, and an AI assistant that builds alongside you.

## Finance as Code

Because the model is code, it inherits the properties software teams rely on:

| Property | What it means for the cost model |
|---|---|
| **Reviewable** | Every change is a branch and a pull request; a colleague sees exactly what moved before it ships |
| **Reproducible** | A tag pins a configuration version to the cost periods it applies to, so a historical run replays exactly |
| **Portable** | The model is open text in a repository you own — not rows in a proprietary database |

## Two ways to build the same model

<CardGroup cols={2}>
  <Card title="Visual forms" icon="table-cells">
    Fill in a form per configuration, with **per-stage validation** and field help. Columns and connections are picked from lists, not typed. Fits most authoring and anyone comfortable with a settings screen.
  </Card>
  <Card title="Direct configuration" icon="code">
    Edit the underlying configuration text, with **autocomplete** as you type and the same validation. Fits bulk edits, copying a pattern, or reviewers who prefer to read the whole thing.
  </Card>
</CardGroup>

Both edit the same files. Switch between them whenever you like — nothing is lost either way.

## Sign in for the rich experience

<Warning>
Signed out, the editor is a plain text view of your repository. **The schema browser, autocomplete, and AI chat are available only when you're signed in** — with the same identity you use for the web app. If the editor looks like a text editor and nothing more, sign in first. See [Set up the editor](/authoring/set-up-the-editor).
</Warning>

## What you see in the editor

- **Stages** tree — Connect, Model (Prepare, Normalize, Enrich, Allocate), Build, Engage. Right-click a stage to **add a new configuration** to it.
- **Data** folder — the datasets and sources the model refers to.
- **Validate Configuration** — checks the whole model against each stage's rules without running it.
- Top bar — the **AI chat**, **schema browser**, and **account** icons.

Within **Enrich** and **Allocate**, rules run in the order they're listed. Each rule is numbered (100, 200, 300…) so there's room to insert one between two existing rules without renumbering.

## Two surfaces, one model

| Surface | What it's for |
|---|---|
| **Web app** — [app.stitcher.ai](https://app.stitcher.ai) | Operate the model: environments, data connections and their credentials, runs, schedules, tags, assistant sessions |
| **StitcherAI Editor** | Build the model: configurations, forms, chat, validation, version control |

Credentials never live in the repository. A configuration refers to a connection **by name**; the web app holds the secret — see [Connections & credentials](/connections-and-credentials).
