StitcherAI models the **total cost of technology**. Cloud bills, SaaS and API usage, AI-provider spend, internal and custom cost, and signed vendor contracts all land in **one cost model**, normalized to [FOCUS](/data-foundation/focus). A team's cost is the sum of everything it consumes across every kind of spend — not one provider's bill in isolation.

## Three inputs build the model

<CardGroup cols={3}>
  <Card title="Cost data" icon="file-invoice-dollar">
    Cloud billing exports, SaaS/API usage feeds, AI-provider cost and usage, custom cost files, PDF invoices, and parsed contracts. Every row is normalized to FOCUS.
  </Card>
  <Card title="Business data" icon="sitemap">
    Ownership, teams, cost centers, headcount, revenue, budgets. The context that attributes spend, drives allocation, and gives KPIs a denominator.
  </Card>
  <Card title="Telemetry" icon="wave-square">
    Usage emitted by your own applications — used primarily for [AI cost management](/cost-model/ai-cost-management): token- and trace-level AI usage that a bill cannot carry, revealing which feature, team, or customer drove the spend.
  </Card>
</CardGroup>

Every input flows through the same [pipeline](/pipeline/overview): **Connect → Model → Build → Engage**. A source is normalized to FOCUS, [attributed and allocated](/pipeline/model/allocate), built into [artifacts](/pipeline/build/generate-artifacts), [governed](/pipeline/build/govern), and delivered. Nothing about the pipeline changes because a source is a contract rather than a cloud bill.

## Why one model rather than five

| Because spend shares one model… | …you get |
|---|---|
| Every row carries the same FOCUS columns | Costs that are **comparable across providers** |
| Allocation rules see every kind of spend | A SaaS invoice and cloud compute both land on `team-platform` and reconcile to the same total |
| Artifacts are built over the whole model | **One chargeback, one forecast base, one set of KPIs** spanning cloud, SaaS, AI, and contracts |

<Note>
Each source is populated to the extent its data supports — the guaranteed-versus-best-effort discipline described in [FOCUS](/data-foundation/focus). StitcherAI does not manufacture definition that isn't present in the source.
</Note>
